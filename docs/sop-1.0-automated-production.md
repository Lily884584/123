# AI PPT Studio

Automated PPT Production SOP

版本：1.0

## 项目目标

建立一套专业级 AI PPT 自动化制作系统。

用户只需要上传客户资料，并输入制作需求，系统自动完成文件解析、资料研究、模板搜索、设计分析、PPT 大纲生成、三套样稿制作、质量检查和最终 PPT 生成。

用户不需要手动操作中间流程。

## 一、核心工作模式

系统必须支持三种制作模式。

MODE A：客户需求生成 PPT

用户提供制作要求，AI 自动研究主题、规划内容、搜索模板并生成 PPT。

MODE B：参考图片或模板生成 PPT

用户上传 PPT 页面截图、设计图片或 PPTX 模板。

AI 分析参考设计，提取视觉规范，并根据客户内容生成新 PPT。

MODE C：已有内容与模板重新设计

用户提供原始 PPT、PDF、Word 等内容，以及参考模板。

AI 提取原始内容，结合新模板重新设计。

系统默认采用智能判断模式，自动选择最合适的制作路径。

## 二、输入管理

所有用户上传文件统一放入：

input/customer_files/

参考图片放入：

input/reference_images/

参考 PPT 模板放入：

input/reference_templates/

支持格式：

PPTX、PDF、DOCX、XLSX、TXT、MD、PNG、JPG、JPEG。

系统启动时自动扫描文件夹。

要求：

1. 自动识别文件格式。
2. 自动读取文件大小。
3. 自动生成文件清单。
4. 自动检查损坏文件。
5. 原始文件不得修改。
6. 支持多个文件同时处理。
7. 大文件必须采用分批解析。
8. 不允许把所有文件内容一次性放入模型上下文。

客户项目落地后，这些路径落在每个项目目录内，见 SOP 1.1，不使用全局共享的客户输入目录。

## 三、文件解析 Agent

负责解析所有客户资料。

PPTX：使用 python-pptx 提取文字、页面结构、图片和图表信息。

PDF：使用 PyMuPDF 提取文字、表格和页面信息。

DOCX：使用 python-docx 提取段落和表格。

XLSX：使用 openpyxl 提取工作表、表格和数据。

图片：提取图片尺寸，并交给支持视觉输入的模型分析。

对于 PPTX 和 PDF：必须支持页面渲染。

输出：workspace/extracted_content/

每个文件建立独立解析结果。保留原始文件名、来源和页码信息。

## 四、客户需求分析 Agent

分析用户输入的需求。

提取：

1. PPT 主题。
2. 使用场景。
3. 目标受众。
4. 预计页数。
5. 语言。
6. 设计风格。
7. 内容深度。
8. 图片需求。
9. 图表需求。
10. 是否需要联网研究。
11. 是否需要使用指定模板。

生成：workspace/requirements/requirement_analysis.md

如果用户没有提供页数或风格，可根据内容提出合理默认方案，不要频繁打断用户。

## 五、Research Agent

负责联网研究和模板搜索。

资料搜索：根据主题搜索可靠的资料。重要数据必须记录来源。不能编造数据、案例和引用。

模板搜索网站：

1. Slidesgo
2. SlidesCarnival
3. Canva
4. Envato Elements

优先使用官方网站提供的搜索和下载能力。

如果没有公开 API：可以使用搜索引擎查找公开页面。

不得绕过登录、付费、访问控制或反爬机制。

需要用户登录、购买或人工确认时，暂停该操作并请求用户确认。

搜索结果保存：workspace/template_candidates/

每个候选模板记录：

- 名称
- 来源网站
- 页面地址
- 预览图片
- 设计风格
- 是否提供 PPTX
- 下载条件
- 授权类型
- 是否允许商业使用
- 是否允许修改
- 署名要求

未经授权的模板不得进入商业交付流程。

## 六、Template Analysis Agent

负责分析候选模板。

分析内容：

1. 页面比例。
2. 背景颜色。
3. 主色和辅助色。
4. 字体。
5. 标题样式。
6. 正文样式。
7. 图片布局。
8. 图表布局。
9. 页面结构。
10. 装饰元素。
11. 留白和间距。

建立 Design System：workspace/design_system/

输出：

- design_tokens.json
- color_palette.json
- typography.json
- layouts.json
- template_rules.md

允许参考多个模板，但必须保证最终 PPT 风格统一。

## 七、PPT 内容规划 Agent

根据客户资料和研究结果建立 PPT 故事线。

输出：workspace/outlines/ppt_outline.md

每页必须包含：

- 页码
- 页面标题
- 页面目的
- 核心观点
- 支持数据
- 图片建议
- 图表建议
- 推荐布局

内容必须有逻辑递进。避免重复内容。避免大段文字。不允许为了达到页数而制造无意义页面。

## 八、双引擎制作系统

ENGINE B：模板智能填充。

适用条件：找到合适且授权允许的 PPTX 模板。

执行：

1. 解析原始模板。
2. 识别页面布局。
3. 匹配客户内容。
4. 填充文字。
5. 替换图片。
6. 更新图表。
7. 调整排版。
8. 保留原模板设计特点。

优先保留原始 PPTX 的可编辑元素。

ENGINE C：设计语言提取与重新设计。

适用条件：原始模板不适合直接使用，或者需要更自由的页面布局。

执行：

1. 提取模板设计规范。
2. 建立 Design System。
3. 根据内容规划页面。
4. 选择合适布局。
5. 生成页面。
6. 插入图片。
7. 创建图表。
8. 统一整体风格。

不得简单地将参考图片直接作为整页背景。

## 九、三套样稿生成

必须生成三套具有明显差异的设计方案。

方案 A：高端极简风。

方案 B：商业咨询风。

方案 C：科技创意风。

AI 可以根据客户需求调整三个方案的具体定位。

每套生成 3-5 页。三套方案必须使用相同的核心内容，方便用户比较。

每套必须包含：

1. 封面。
2. 目录或章节页。
3. 内容分析页。
4. 数据图表页。
5. 总结或解决方案页。

输出：

- output/proposal_A/
- output/proposal_B/
- output/proposal_C/

每套包含：

- sample.pptx
- preview/
- design_description.md

## 十、质量检查 Agent

内容检查：

- 是否偏离客户需求。
- 是否存在重复内容。
- 是否有虚构数据。
- 是否有错误引用。
- 是否存在逻辑问题。

视觉检查：

- 是否文字溢出。
- 是否元素重叠。
- 是否图片变形。
- 是否字体不统一。
- 是否页面过于拥挤。
- 是否整体风格一致。

技术检查：

- PPTX 是否能够正常打开。
- 页面数量是否正确。
- 图片是否完整。
- 图表是否正常。
- 字体是否存在替换问题。

使用 LibreOffice 将 PPTX 转换为 PDF 或图片进行视觉检查。

发现问题后：修改，重新渲染，再次检查。最多自动修复三轮。仍然无法解决的问题记录到报告中，不得假装通过检查。

## 十一、用户确认机制

三套样稿完成后：停止完整 PPT 的生成。

向用户展示：

1. 三套 PPT 预览。
2. 每套设计风格说明。
3. 每套优缺点。
4. 模板来源和授权情况。
5. 推荐方案。

等待用户选择：A、B 或 C。用户也可以提出修改意见。

未经用户确认，不得开始最终完整 PPT 的生成。

## 十二、最终 PPT 生成

用户选择方案后：

1. 按照选定的 Design System 制作全部页面。
2. 统一字体和颜色。
3. 检查所有页面。
4. 检查数据来源。
5. 检查图片授权。
6. 生成最终 PPTX。
7. 同时生成 PDF 预览。
8. 保存完整项目资料。

输出：output/final/

最终文件：

- final_presentation.pptx
- final_presentation.pdf
- production_report.md

## 十三、开发规范

1. 不允许一次性开发所有模块。
2. 必须检查现有项目代码。
3. 不得随意删除已有功能。
4. 所有模块必须独立。
5. 所有 API Key 必须使用环境变量。
6. 原始客户资料必须只读。
7. 每个阶段都必须能够独立运行。
8. 每个阶段都必须有测试。
9. 所有输出文件必须保留版本。
10. 所有错误必须记录日志。

模型调用必须使用可配置的模型接口。Cursor 内置订阅模型不能默认作为外部程序的 API 使用。

## 十四、开发执行顺序

Phase 1：建立项目 SOP 和目录结构。

Phase 2：实现本地文件扫描与解析。

Phase 3：实现客户需求分析。

Phase 4：实现模板搜索与授权记录。

Phase 5：实现 PPTX 模板解析和设计分析。

Phase 6：实现 PPT 大纲和页面内容生成。

Phase 7：实现 B、C 两种 PPT 生成引擎。

Phase 8：实现三套样稿生成。

Phase 9：实现自动质量检查。

Phase 10：实现用户选择和最终 PPT 生成。

每个阶段完成后：运行测试，检查输出，更新开发文档，Git 提交，再进入下一阶段。

## 最终目标

用户只需要：

1. 上传客户资料。
2. 输入 PPT 制作需求。

系统自动完成其余所有工作。

唯一必须保留的人工确认环节：用户选择三套样稿中的最终设计方案。
